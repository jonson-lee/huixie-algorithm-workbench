# 第一次产品更新需求

## 版本目标

目标版本为 `0.2.0`。本次更新把“回写”从面向算法零基础学生的教学工作台，调整为面向已有编程经验用户的算法记忆与复习工具。

核心价值是帮助用户记住一道题的识别信号、关键步骤和 Python 写法，而不是提供完整的入门课程。

## 已确认范围

### 1. 用户与语言

- 目标用户是已经具备编程经验、能够阅读和编写 Python 的开发者。
- 产品只支持 Python 3，不在本次更新中加入 Java、C++、Go 或其他语言。
- 解释默认使用已有编程基础的表达，不重复讲解变量、循环、函数和基础语法。

### 2. 核心复习机制

- 主流程保持简洁，围绕“回忆 → 默写 → 对照 → 安排复习”展开。
- 页面优先展示题目识别信号、函数签名、记忆提示和当前复习动作。
- 长篇文字与完整代码不直接铺在主页面中；用户主动操作后，通过抽屉、折叠区或独立详情视图查看。
- 复习结果结合本地测试与用户自评，继续采用透明、无需 AI 的间隔规则。

### 3. 一题多解

- 数据结构支持一道题保存多种 Python 解法。
- 每种解法包含：名称、核心思路、关键步骤、时间复杂度、空间复杂度、易错点、Python 代码和可选参考来源。
- 内置 Hot 100 内容优先提供 2～3 种有明显差异且有记忆价值的解法，不为增加数量重复收录同质写法。
- 选材优先参考 LeetCode／力扣中浏览量高、解释质量好的公开题解，重点关注 Krahets 和灵茶山艾府的思路。
- 不复制其原文、图片、示例或长段代码；站内内容必须独立总结、独立编写，并保留作者名称和原文链接作为参考来源。

### 4. 题库结构

- 产品内置 Hot 100 题库，作为默认只读题库。
- 用户可以导入、创建、编辑、分组、排序、删除和导出自己的题库。
- 自定义题库允许携带题目摘要、多种题解、Python 代码和测试用例。
- 自定义题库与内置题库分开标识，避免用户误认为自定义内容由产品维护或验证。

### 5. 导入与本地数据

- 第一次更新以版本化 JSON 作为正式导入与导出格式，不以 CSV 承载多行代码和多种解法。
- 导入内容按不可信数据处理：校验结构、以纯文本渲染说明、禁止直接注入 HTML。
- 用户代码只在现有 Pyodide Worker 中执行；导入内容不能获得页面脚本权限。
- 题库、代码和复习状态继续默认只保存在本机，不要求账号或云同步。
- 为容纳多题库和多份代码，存储层从 `localStorage` 迁移到 IndexedDB；迁移时保留现有学习进度。

## 本次更新不包含

- 多语言代码执行。
- 自动抓取、批量搬运或镜像 LeetCode／力扣题面与题解。
- LeetCode／力扣账号、Cookie、提交记录或代提交能力。
- 云端同步、社区、排行榜、聊天式助教和付费 AI。
- 服务器端权威判题。

## 验收标准

- 用户可以在内置 Hot 100 与自定义题库之间切换。
- 用户可以导入包含题目、题解、Python 代码和测试用例的合法 JSON，并得到明确的成功或错误反馈。
- 用户可以管理和导出自定义题库，刷新页面后数据仍然存在。
- 每道题可以展示多个解法，但主复习页面默认不出现长篇题解和完整代码。
- 导入的说明不会被当作 HTML 执行，导入的代码只通过 Worker 运行。
- 现有 `localStorage` 学习记录可以迁移，升级后不会静默丢失。
- 内置内容的参考来源可追溯，站内文字和代码保持独立创作。
